# ADR 0003: 裏の処理は Queues ではなく waitUntil で行う

- Status: Accepted
- Date: 2026-11-04

## Context

登録は「1着3秒」が目標。背景の切り抜きとタグ付けは数秒かかるので、応答を待たせずに裏で進めたい。

## Decision

`POST /api/items` は写真を R2 に保存して即座に応答し、切り抜きとタグ付けは `ctx.waitUntil` で同じリクエストの中で続ける。失敗したらアイテムを「確認待ち」にする。画面は処理中のアイテムがある間だけ再取得する。

## Consequences

- 追加のインフラ（Queues）や設定が不要
- 失敗時の自動再試行はない。手で直せる状態にして逃がす
- 一度に大量に取り込む機能（数百枚の一括登録など）を作るときは、Queues への移行を検討する

## Alternatives considered

- **Queues**：再試行と流量制御があるが、MVP の規模では過剰。無料プランでの提供状況にも依存する
- **画面から2回目のリクエストで処理させる**：画面を閉じると処理が止まる
