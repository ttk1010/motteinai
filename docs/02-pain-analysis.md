# 02. ペイン分析

## 1. 出発点の悩み

> 服を買いに行っても結局どんな服を買っていいかわからず、似通った服や手持ちと組み合わせづらい服を買いがち。

この一文を分解すると、失敗が3種類ある。

| 失敗 | 結果 | 起きる場面 |
|---|---|---|
| F1 何を買えばいいか分からない | 目的なく店を回る。店員のすすめや目についた物で決める | 買い物の**前** |
| F2 似た服を買う | 同じような服が増え、組み合わせの数は増えない | 店頭で**決める瞬間** |
| F3 手持ちと合わない服を買う | 単品では良くても着られず、出番がない | 店頭で**決める瞬間** |

## 2. なぜ起きるか（根本原因）

### F2・F3：店頭で「手持ちの記憶」が使えない
1. **思い出せる量に限界がある**。持っている服の大半は、店では思い出せない。思い浮かぶのはよく着る数着だけで、それに似た物をまた選んでしまう。
2. **好みが固定されている**。人は好きな色や形を繰り返し選ぶ。好みとしては正しいが、結果として「似た服」が増える。
3. **単品で判断してしまう**。店では、その服1着だけを見て「良い」と判断する。手持ちと合わせたときの姿は頭の中で組み立てるしかないが、それは難しい。
4. **その場の勢いに流される**。セール、店員のほめ言葉、試着したことへの申し訳なさ。冷静になる時間がない。
5. **確認の手間が大きい**。今あるアプリで「似た服を持っていないか」を調べるには、アプリを開いてカテゴリを探して…と手順が多く、レジの前ではやらない。

### F1：「足りない物」が見えない
1. 手持ちの**全体像を見ていない**ので、何が欠けているかが分からない。
2. 「足りない物」は**単品ではなく、組み合わせの中で決まる**。例えば、柄物のボトムが3本あるのに、それに合う無地のトップスがない。人の頭で数えるのは無理。
3. 一般的な「揃えるべき定番リスト」は、その人の手持ちを考えていないので役に立たない。

### 管理アプリが続かない理由
1. **最初の登録が重い**（1着30〜60秒 × 数十着）。
2. **価値が出るまでが遠い**。数十着入れないと提案が意味を持たない。
3. **入力に完璧さを求められる**。カテゴリ・色・素材・季節…と項目が並ぶと、正しく埋めないといけない気がする。
4. **使う場面がない**。毎朝のコーデ決めに困っていない人には、開く理由がない。

## 3. ユーザー像

**主なユーザー**：20〜30代。服は好きで、毎シーズン何着か買う。でも「似た服ばかり」「買ったのに着ない」が続いていて、少しうんざりしている。毎朝のコーデは何となく決められている。困っているのは**買う瞬間**。

| 項目 | 内容 |
|---|---|
| 服の数 | 50〜150着 |
| 買い物 | 月1〜2回。店舗とECが半々 |
| スマホ | 店頭・通勤中・寝る前に片手で使う |
| 求めること | 「これ買っていい？」に**数秒で、理由つきで**答えてほしい |
| 求めないこと | おしゃれ指南、他人のコーデ、送客、長い文章 |

## 4. やりたいこと（Jobs to be Done）

| # | 場面 | やりたいこと | 今の代わりの手段 |
|---|---|---|---|
| J1 | 店で服を手に取ったとき | **これを買って後悔しないか**、すぐ知りたい | 記憶、勘、店員 |
| J2 | 買い物に行く前 | **何を買えば手持ちが一番活きるか**知りたい | 雑誌・SNSの定番リスト |
| J3 | ECで見ているとき | J1と同じことを、スクショやURLで確かめたい | 記憶 |
| J4 | 朝・前日の夜 | 手持ちで**組める**コーデ、特に普段着ていない服を使ったコーデを知りたい | 鏡の前で試す |
| J5 | 服が増えたとき | 手間をかけずに記録したい | なし／放置 |

**最優先は J1 と J2**。J4 はアプリを開く習慣を作り、データを増やす役割。J5 は全ての前提。

## 5. 設計の方針（ペインと対策）

| 原因 | 対策 | 対応する機能 |
|---|---|---|
| 思い出せない | 判断のときにアプリが**手持ちを代わりに覚えている** | 買う前チェック |
| 単品で判断してしまう | 手持ちと**合わせた姿**と、**組み合わせの数**を見せる | 買う前チェック／＋N通り |
| 好みが固定されている | 似ている度合いを**％と写真**で突きつける | 似ている手持ち |
| その場の勢い | **判定を1つだけ**出して、迷う時間を減らす | 判定（買い／保留／見送り） |
| 確認の手間 | **起動から結果まで1回撮るだけ** | ホーム画面のショートカット、カメラから始まる |
| 足りない物が見えない | 「これを足すと何通り増えるか」で**順位をつける** | 買うと良い服 |
| 登録が重い | **連続撮影、AIが自動入力、確認は後回し** | 連続撮影登録／確認待ちの受信箱 |
| 価値が遠い | **10着から提案が出る** | 初回の流れ |
| 完璧さを求められる | 必須の入力は**写真だけ**。修正したいときだけ直す | タグ自動入力 |
| 使う場面がない | 店頭（J1）と朝（J4）の2つの入口を作る | 今日／買い物タブ |

## 6. 成功の指標

| 指標 | 目標 |
|---|---|
| 1着あたりの登録時間（撮影〜保存） | 5秒以下 |
| 初回起動から10着登録まで | 3分以下 |
| 買う前チェック：撮影から判定表示まで | 4秒以下（体感） |
| 判定を見て買うのをやめた割合 | 測るだけ（目標値は置かない） |
| 30日後の「出番なし」の服の割合 | 減っていること |
