# 03. UX設計

仮のプロダクト名：**Kumi**（「組む」から）

## 0. 設計の原則

1. **カメラが最初にある**。登録も買う前チェックも、まずカメラが開く。メニューを挟まない。
2. **必須は写真だけ**。それ以外はAIが埋める。直すのは間違っているときだけ。
3. **待たせない**。保存はすぐ終わり、重い処理は裏で進める。画面は必ずスケルトンから始まる。
4. **答えを数字で出す**。「＋12通り」「似ている 87%」。形容詞の説明はしない。
5. **言葉を足さない**。キャッチコピー、励まし、説明文は入れない。ラベル、数字、操作だけ。
6. **動きで伝える**。どこから来てどこへ行ったのか、を毎回アニメーションで見せる。
7. **売り込まない**。外部ECへ誘導しない。「見送り」をはっきり出す。

## 1. 情報設計

```
[今日]  [クローゼット]  (＋)  [買い物]  [自分]
```

| タブ | 役割 | 中身 |
|---|---|---|
| 今日 | 朝の入口（J4） | 天気、今日のコーデ3案、着た記録、出番のない服を使う1案 |
| クローゼット | 一覧と管理 | 一覧（カテゴリ／色／出番で並べ替え）、アイテム詳細、確認待ち |
| ＋ | 登録（J5） | **押すとすぐカメラ**。長押しで「買う前チェック」 |
| 買い物 | 店頭とその前（J1〜J3） | 買う前チェック、買うと良い服、気になるリスト |
| 自分 | 設定 | アカウント、身長などの好み、データの書き出し・削除、ログアウト |

- 下のタブは1枚のガラスのバーで、選ばれているタブには液体のように形を変える目印が付く。
- ＋はタブバーの中央に浮く丸いガラスのボタン。
- PWAのショートカット：「買う前チェック」「登録」を、ホーム画面のアイコン長押しから直接開ける。

## 2. 主な流れ

### 2.1 初回（10着で最初の提案まで）

```
Googleでログイン
  → 好み（任意・1画面）：服の傾向（メンズ / レディース / 両方）、住んでいる地域（天気用・位置情報でも可）
  → カメラ（連続撮影）
     画面上部に輪の進み具合「3 / 10」
  → 10着目でカメラの上にカードが出る：「コーデ 14通り」→ 今日タブへ移動
```
- 説明画面やチュートリアルは置かない。ボタンの位置で分かるようにする。
- 10着の目安：トップス4・ボトム3・アウター1・靴2。カテゴリはAIが判定するので、ユーザーは数を意識しなくていい。偏りがあれば輪の横に足りないカテゴリのアイコンだけ出す。
- 途中で閉じても、登録した分は保存されている。

### 2.2 登録（1着3秒）

```
(＋) をタップ
  → カメラがすぐ開く（下で 撮影 / 写真から / URL・スクショ を切り替え）
  → シャッターを押す → 写真が右下の置き場へ飛ぶ → すぐ次を撮れる
  → 完了
  → クローゼットに即追加（処理中は光が流れる表示）
  → 裏で：背景を切り抜く → AIがタグを付ける → 似ている手持ちを調べる
  → 確認待ちに入る（任意）
```

**撮るとき**
- 置き場（右下）に小さな画像が重なっていく。数字のバッジ付き。
- 失敗した1枚は、置き場を上にスワイプすると消せる。
- 撮影のコツは文字で書かない。カメラの枠に薄いガイド線を出すだけ。

**写真から**：まとめて選べる（最大50枚）。

**URL・スクショ**：
- EC商品ページのURLを貼る → サーバーが商品画像を取ってくる（OGP画像）。
- スクショ → そのまま切り抜き。
- 共有メニュー（Web Share Target）から、ブラウザで見ているECのページを直接送れる。

**確認待ち（任意）**
- クローゼットの上に「確認待ち 12」の札。
- カードを重ねて表示する。各カードは切り抜いた画像と、AIが付けたタグ（カテゴリ・色・柄・季節・きちんと度）。
- 右へスワイプで確定。タグを押すと候補がその場で並び、選ぶだけで直る。
- 確認しなくても、提案やチェックにはそのまま使われる（AIの判定を使う）。

**入力項目**

| 項目 | 入力 | 備考 |
|---|---|---|
| 写真 | **必須** | |
| カテゴリ・細かい種類 | AI | トップス＞Tシャツ など |
| 色（主色・差し色） | AI＋画像の画素解析 | 主色はLab色空間で持つ |
| 柄 | AI | 無地 / ストライプ / チェック / 柄物… |
| きちんと度 | AI | 1〜5 |
| 季節・暖かさ | AI | |
| シルエット | AI | ゆったり / 普通 / 細め |
| ブランド・価格・購入日 | 任意 | 着用1回あたりの値段に使う |

### 2.3 買う前チェック（最重要）

```
(＋) を長押し ／ 買い物タブ ／ ホーム画面ショートカット
  → カメラ（URL・スクショにも切り替え可）
  → 撮る
  → 下から結果のシートが上がってくる（4秒以内。項目ごとにスケルトンから順に埋まる）
```

**結果シートの中身（上から）**

1. **判定**：`買い` / `保留` / `見送り`。1つだけ、大きく。理由を1行（例：`似ている手持ち 2着` `合う手持ち 9着`）。
2. **増える組み合わせ**：`＋12通り`。数字は0から数え上がる。下に組み合わせの例を3つ、手持ちの服の画像を並べて見せる。
3. **似ている手持ち**：上位3着と、似ている度合い（%）。85%以上は「ほぼ同じ」として赤みのある色で表示。
4. **合う手持ち**：カテゴリごとの横スクロール。出番のない服と合うものには印を付ける（その服が活きる）。

**操作**
- `気になるリストへ`：あとで比べる。
- `買った`：**撮った写真をそのまま登録する**（撮り直し不要。登録の流れに合流）。
- 閉じる：撮った写真は残さない。

**判定ルール（初期案）**

| 条件 | 判定 |
|---|---|
| 似ている度合い ≥ 85% の手持ちがある | 見送り |
| 増える組み合わせ ≥ 基準値、かつ 似ている度合い < 70% | 買い |
| それ以外 | 保留 |

基準値は手持ちの数によって変える（例：手持ちのコーデ総数の5%）。最初はルールで判定し、AIは理由の言い回しにだけ使う。

### 2.4 買うと良い服（J2）

```
買い物タブ → 「買うと良い服」
  → 上位5件をカードで表示：
     [アイテムの見本図]  白のオックスフォードシャツ
     ＋18通り ／ 合う手持ち：ネイビーのスラックス、ベージュのチノ…
     活きる服：出番なしの グリーンのカーゴ
  → カードを押す：組み合わせの例、色の候補、似ているので避けるべき物
  → 「買い物リストに入れる」 → 店ではリストを見ながら回れる
```
- 候補は**定番アイテムの見本集**（約150種：カテゴリ × 色 × 柄 × きちんと度 × シルエット）から選ぶ。特定ブランドの商品ではない。
- 順位の付け方（下の §4.3）は「組み合わせが何通り増えるか」が中心。手持ちと似ている物は外す。季節と、実際によく着る傾向で重みを付ける。
- 買い物リストの項目を店で撮ると、そのまま買う前チェックになる（候補と似ていれば「リストの物」と表示）。

### 2.5 今日（J4）

- 一番上：天気（最高・最低気温、雨）。地域はプロフィールで設定。
- **コーデ3案**：カードを重ねて表示し、横スワイプで切り替え。服の画像を体の位置に並べた絵。
- カードの下：`これを着る`（着た記録になる）。案を入れ替えたい服を押すと、その服だけ別の候補に変わる。
- 3案のうち1案は必ず**出番のない服**を使う（小さな印を付ける）。
- 着た記録は、1日1回のタップだけ。記録しなくても困らない。

### 2.6 クローゼット

- 3列の一覧。切り抜き画像を淡いガラスのタイルに乗せる。
- 上部の絞り込み：カテゴリ、色、季節、`出番なし`、`確認待ち`。
- 並べ替え：新しい順 / 色順（色相で並べる、虹のように見える） / 着た回数。
- **アイテム詳細**（一覧から画像が拡大しながら移動）
  - 組める数（`このアイテムで 23通り`）
  - 似ている手持ち
  - 着た回数、最後に着た日、1回あたりの値段
  - タグの編集、削除（削除は下にスワイプで取り消せる通知を出す）

## 4. 提案の仕組み（UXに関わる部分）

### 4.1 コーデの組み立て
- 形：`トップス + ボトム` または `ワンピース`。気温に応じてアウターを足す。靴は持っていれば足す。
- 点数（ルール。説明しやすさを優先）
  - 色：無彩色の割合、使っている色は3色まで、色相同士の相性
  - きちんと度の差が小さいほど高い
  - 柄物は1点まで
  - シルエット：ゆったり × 細め を高く
  - 季節・気温に合っているか
  - 最近着た組み合わせは下げる
- 上位の候補から、AIが3案を選んで並べる（多様さを優先）。

### 4.2 似ている度合い
- アイテムを属性で表した数値（カテゴリ・Labの色・柄・シルエット・きちんと度）同士の距離と、AIが書いた説明文の意味の近さを合わせて出す。
- 手持ちは多くても数百着なので、その場で全件と比べられる。

### 4.3 「＋N通り」
- 候補を足したときに**新しく成り立つコーデの数**（点数が基準以上のもの）。
- 買う前チェック、買うと良い服、アイテム詳細の3か所で同じ計算を使う。数字の意味がどこでも同じになるようにする。

## 5. 見た目：Liquid Glass（白基調）

| 要素 | 仕様（初期値） |
|---|---|
| 背景 | `#F7F8FA` の上に、ごく淡い色のにじみを2〜3個ゆっくり動かす（ガラスが見えるように） |
| ガラス | 白 55%、背景ぼかし 24px、彩度 180%、内側に白い光の縁（上が明るい）、柔らかい影 |
| 屈折 | 対応ブラウザではSVGの歪みフィルタで縁を屈折させる。非対応の環境ではぼかしだけ |
| 角 | カード 28px、シート 32px、札 999px |
| 文字 | 日本語は Noto Sans JP、数字は Inter（等幅数字） |
| 色の役割 | 文字 `#0B0B0F` 90%／淡い文字 50%。判定：買い＝緑みの青、保留＝灰、見送り＝赤みの橙 |
| アイコン | 線が細めのアイコンセット1種類に統一 |

- **白い背景にガラスを乗せただけでは見えない**。そのため背景の色のにじみ、影、縁の光で輪郭を出す。
- 文字はガラスの上でも読みやすいコントラストを確保する（WCAG AA）。

## 6. アニメーション

| 場面 | 動き |
|---|---|
| タブ切り替え | 目印のしずくが伸びて次のタブへ移る（ばねの動き） |
| ＋を押す | ボタンが広がってカメラ画面になる |
| シャッター | 画面が白く一瞬光り、撮った画像が縮みながら置き場へ飛ぶ |
| 処理中のアイテム | 光の筋がタイルの上を流れ、終わると切り抜き画像が浮かび上がる |
| 一覧 → 詳細 | 画像がそのまま拡大して移動する（共有要素の遷移） |
| 結果シート | ばねで下から上がる。項目ごとに少しずつ遅れて表示 |
| ＋N通り | 0から数え上がる。数字が決まると軽く弾む |
| 判定の札 | 少し大きく出てから元の大きさに戻る |
| 確認待ち | カードを指で投げられる。手を離した勢いで飛ぶ |
| 札（タグ） | 選ぶと少し膨らむ |
| 引っ張って更新 | ガラスのしずくが伸びて、ちぎれる |
| 削除 | タイルが縮んで消え、周りが詰めて動く |
| 背景 | 色のにじみがゆっくり漂う（20秒周期） |

- 時間：小さな反応 120〜180ms、移動 280〜420ms、ばね（硬さ 300・減衰 30 くらい）。
- `prefers-reduced-motion` が有効なら、移動と弾みをやめて、ふわっと切り替わる表示だけにする。
- アニメーションは `transform` と `opacity` だけで作る（なめらかさのため）。

## 7. スケルトン表示（全画面）

| 段階 | 方法 |
|---|---|
| 最初の表示（JS読み込み前） | `index.html` にアプリの外枠（タブバー・ヘッダー）のスケルトンを直接書いておく |
| 画面の切り替え | 画面ごとに、本番と同じ配置のスケルトンを用意する。データ待ちのあいだ表示 |
| 画像 | 保存時に主色を記録しておき、その色で塗った下地 → 画像が読み込まれたらふわっと表示 |
| 結果シート | 判定・＋N通り・似ている手持ち・合う手持ち、の4つの枠が、それぞれ届いた順に埋まる |
| 処理中のアイテム | タイルの形のまま光の筋を流す |

- スケルトン自体もガラスの見た目にして、光の筋が斜めに流れるようにする。
- スケルトンから本物への切り替えは、ずれずに重なるように同じ大きさで作る。
- 300ms未満で読み込みが終わる場合はスケルトンを出さない（チラつき防止）。

---

## 8. 文言のルール

- 画面に出す言葉は、**ラベル・数字・操作**だけ。
- 「素敵なクローゼットを作ろう」などの文は一切入れない。
- データがない状態も、アイコンと操作ボタン1つで伝える（例：カメラのアイコン＋`撮る`）。
- エラーは何が起きたかと、何をすればいいかだけ（例：`通信できません` `再試行`）。

| クローゼット一覧・詳細 | |
| データの書き出し・アカウント削除 | |
